# Specialist Planner v0.7.0 — Staging Readiness

## Architecture

The Program document remains the single private owner of Classes, Timetable, Progress, Teaching Sessions and Units. v0.7 adds `schoolYears`, `terms` and `nonTeachingPeriods` to the same authoritative planner document. Term Overview is derived at render time and does not introduce a second planning dataset.

## Schema and migration

- Planner schema: 10 (from v0.6 schema 9).
- Cloud Program schema remains 1.
- Existing cloud Program documents with `plannerSchemaVersion: 9` are accepted, upgraded in memory, and written as schema 10 only after a normal revision-checked save.
- Local storage, JSON backup imports and UID-scoped offline cloud caches accept schema 9 and migrate through the same validator.
- Unit, Lesson, Class, Teaching Session, Program and progress reference IDs are preserved.
- Unit/Lesson timestamps use the prior planner timestamp when migrating, making the transformation deterministic.
- No legacy local copy is cleared by the schema migration.

## Academic calendar

School Year, Term and non-teaching dates are manually editable and contain no hard-coded regional dates. Non-teaching dates suppress scheduled materialisation and bulk completion. A fully non-teaching week is skipped by configured week navigation and omitted from Term week numbering.

## Unit Library

Units and Lessons remain Program-owned and subject-agnostic. Optional metadata includes teacher notes, HTTPS resources, curriculum framework/codes/notes, timestamps and schema version. Mandarin Lessons may additionally store an optional `vocabularySetId`; vocabulary content remains owned by The Mandarin Room.

## Security compatibility

Firestore ownership and membership fields remain immutable. Rule changes allow an existing owner-scoped Program to move only from planner schema 9 or 10 to schema 10 while retaining revision, mutation ID and owner checks. There is no sharing or cross-owner read path.
